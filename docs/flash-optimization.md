# UI 精简与 Flash 优化（2026-11-10）

## 范围

保留主页、下拉栏、电源操作界面，以及菜单中的日历、计算器、环境、游戏、设置、关于。
游戏保留 2048 和记忆方块；设置保留日期时间、变暗/息屏时间和抬腕开关等原有逻辑。

删除计时器、NFC 卡片、心率、血氧、指南针页面及头文件，删除没有入口的充电展示页。
主页没有实际传感器支持的心率占位图块一并移除。
专属资源删除指南针图片、80/100 像素数字字体；其余仍被保留页面引用的字体继续保留。

## 方法

- 六个菜单项使用静态描述表和统一创建函数、点击回调，保留图标样式、右滑返回和滚动位置恢复。
- 删除没有调用者的 SquareLine `ui_helpers.c/h` 及引用，删除回调为空的每秒 UI 定时器。
- 在 `Middlewares/GUI/lv_conf.h` 关闭用不到的控件：图表、刻度、图片、下拉框、键盘、列表、表格、窗口等。默认主题会引用启用的控件类，因此仅删除页面不能释放全部相关代码。
- 保留实际使用的 arc、bar、button、buttonmatrix、calendar/arrow header、label、roller、slider、switch、textarea，以及 flex/grid 布局和默认主题。
- `Middlewares/GUI/lvgl/lv_conf.h` 改为包含同一份项目配置，避免两份配置中的控件、内存池参数不一致。
- GUI 源文件 glob 增加 `CONFIGURE_DEPENDS`，增删源文件后构建系统会重新检查源文件清单。

这里的配置属于 LVGL 应用库，不是 CubeMX 外设配置项，所以修改 `lv_conf.h`，无需改动 `.ioc`。
继续使用现有 `-Os`、LTO 和链接器段回收；没有通过扩大程序分区、占用设置扇区来增加容量。

## 实测结果

同一 Debug 构建、相同链接分区，依据链接器 memory usage：

| 项目 | 优化前 | 优化后 |
|---|---:|---:|
| 程序 Flash（464 KiB） | 460,764 B / 96.98% | 385,836 B / 81.21% |
| 程序区剩余 | 14,372 B / 14.04 KiB | 89,300 B / 87.21 KiB |
| 静态 RAM 预算（128 KiB） | 92,056 B / 70.23% | 91,504 B / 69.81% |

程序区节省 **74,928 B（73.17 KiB）**，约为原程序的 16.26%；静态 RAM 减少 552 B。
RAM 数值包含 LVGL/FreeRTOS 固定内存池，不代表运行时堆的峰值。菜单从 12 行变成 6 行，也减少运行时对象分配，实际堆余量需上板观察。
向量区仍为 408 B；两个 16 KiB 设置扇区保持预留。ELF 总 Flash 加载量为 386,244 B（含向量区）。

## 验证和上板回归

最终固件：`build/Debug/watch.elf`；构建日志：`build/ui-trim-build.log`。
构建成功，仍有原工程的 LVGL 旧 API 弃用提示；不是零警告构建。

已有 ARM 仿真回归通过，共 221 项断言检查：核心逻辑 81、AHT21 24、抬腕 56、低功耗策略 16、tickless 端口 20、运行时时基与电源钩子 24。
`scripts/verify_firmware.py` 检查通过：ELF/复位向量、设置扇区保护、六个任务栈、FreeRTOS 堆和 CubeMX 中断/tickless 配置。
最终 ELF 符号检查确认保留页面仍在，删除页面、指南针图片和专属大号字体不在固件中。

本次改动尚未上板。下载后请检查：

1. 六项菜单顺序、图标与文字、滚动、右滑和 KEY 返回；反复进入退出页面无异常。
2. 日历翻月、计算器四则运算、环境温湿度持续更新、两个小游戏正常操作。
3. 设置修改时间/亮度/变暗/息屏时间/抬腕开关，保存后复位仍生效。
4. 10 秒变暗、15 秒息屏，以及触摸、KEY、抬腕三种唤醒继续正常。

此前用户已确认三种唤醒正常。本轮优化不新增 STOP 深度睡眠；下一阶段先以此固件的上板回归结果为基线。
