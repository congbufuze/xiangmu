# 任务通信与设置保存

本次实现的是屏幕休眠：关闭背光、停止显示刷新，FreeRTOS、RTC、触摸轮询和传感器任务继续运行。没有进入 MCU STOP 模式。

## 任务和资源归属

|任务|CMSIS 优先级|CubeMX 栈深度（word）|实际栈（byte）|职责|
|---|---:|---:|---:|---|
|defaultTask|24|128|512|喂狗、采集内存诊断|
|HardwareInitTas|42|768|3072|初始化硬件、欢迎画面，完成后退出|
|KeyTask|40|192|768|扫描按键，发送命令|
|AHT21Task|16|384|1536|采集已启用的传感器、发布快照、检测抬腕|
|UITask|24|1536|6144|初始化并运行 LVGL、页面导航、背光和休眠状态机|
|DataSaveTask|8|384|1536|合并保存请求，作为唯一的运行期 Flash 写入者|

FreeRTOS heap_4 为 24576 byte；LVGL 自带内存池为 48 KiB，两者独立。应用任务启动时的栈预算合计 13568 byte，另需计入内核任务、控制块、队列、互斥锁、事件组和堆分配开销。HardwareInitTas 退出后其堆空间由 Idle 任务回收。

LVGL 设置 `LV_USE_OS=LV_OS_NONE`，表示所有 LVGL 调用在 UITask 中串行执行。FreeRTOS 本身仍正常工作；无需再创建 LVGL swdraw 任务。FreeRTOS 内核禁用 LTO，应用和界面使用 LTO，避免汇编引用的内核符号被优化掉。

|用途|机制|原因|
|---|---|---|
|按键命令|KEYQueue，深度 8，uint8_t|按顺序处理返回、回主页等命令；队列满记录丢弃数|
|活动、变暗、恢复、熄屏、唤醒|AppEvent 事件组|相同状态请求可合并，无需积压历史状态|
|传感器结果|AppSensorSnapshot + SensorMutex + 更新事件|读者需要最新完整样本；互斥锁只保护结构体复制|
|设置|AppSettings + SettingsMutex|UI 修改、传感器读取抬腕开关、保存任务读取设置|
|保存请求|DataSaveEvent 事件组|多次修改合并，只保存最新设置|
|启动屏障|SystemStartupEvent，持久 READY 位|硬件就绪后各任务才能访问外设|

传感器任务不访问页面、不直接改界面数据。UI 将快照复制到旧的 HWInterface 显示字段，兼容现有页面。RTC 和 LCD 由 UI 使用；启动时 HardwareInitTas 使用 LCD，READY 后移交。CST816、AHT21、MPU6050 的软件 I²C 引脚不同，分别归对应任务使用，没有添加全局 I²C 锁。

已连接的 AHT21 和 MPU6050 通过 `HW_USE_AHT21=1`、`HW_USE_IMU=1` 启用，其他未连接传感器继续禁用。传感器任务填充快照，页面不直接访问传感器总线。

传感器接线：AHT21 SDA=PC9、SCL=PA8；MPU6050 SDA=PB13、SCL=PB14。两模块使用 3.3V 并与核心板共地。MPU6050 默认地址为 0x68（AD0 接地）；当前使用任务轮询，不依赖 INT。软件 I2C 由驱动初始化，无需启用 CubeMX 的硬件 I2C 外设。

AHT21 每约 500ms 触发采样，检查各字节 ACK、忙标志、校准状态和 CRC；失败时保留上次数据并清除快照有效标志，负温度使用浮点转换避免无符号下溢。主页目前显示整数温湿度，只有跨过整数边界才会看到数字变化。熄屏期间继续采样，唤醒后显示最新数据。

抬腕需在设置中开启。当前以模块 +Z 朝向屏幕正面安装为前提，滚转和俯仰角均进入约 34 度以内且连续三个有效样本才确认朝上；离开约 49 度后重新准备下一次抬腕。首次姿态不产生唤醒，水平旋转不算抬腕。亮屏后保持朝上不会持续重置熄屏计时；倾斜放下也不再立即强制熄屏，沿用用户配置的超时。安装方向改变时需要相应变换轴向。DMP 计步使用正常加速度/陀螺仪模式并持续读取 FIFO，避免与加速度低功耗模式混用；当前仍是屏幕休眠，并非 MCU/IMU 的深度低功耗。

调试可观察 `g_app_diagnostics`：`aht_init_status` 和 `imu_init_status` 为 0 表示初始化成功；`aht_read_failures`、`imu_read_failures` 为采样失败计数；`wrist_wake_count` 为识别到的抬腕次数。软件模拟测试入口为 `tests/run_sensor_driver.py`，可分别执行 `tests/sensor_driver_test.c`（24 项 AHT21 驱动检查）及 `tests/wrist_logic_test.c`（56 项抬腕检查）；模拟测试不替代接线及实际姿态验证。

## 屏幕行为

默认亮度 50%，最后一次操作后 10 秒变暗至不超过 10%，15 秒熄屏。两个时间都从最后一次操作计算，熄屏时间必须晚于变暗时间；不合理的组合会将熄屏时间调整到变暗后 5 秒。

按键命令由 UI 同时解释为导航和活动，避免先唤醒、后错误执行导航。熄屏后的第一次 KEY 或触摸只唤醒；触摸保持到松手前不向控件传递。持续按住触摸会刷新活动时间。唤醒优先于同轮到达的熄屏请求。

熄屏时暂停显示刷新定时器并禁止显示失效请求，防止页面定时器又唤起绘制；输入和页面逻辑定时器继续运行，唤醒后恢复失效处理并重绘。第二按键命令的处理仍保留，但当前物理 KeyScan 只产生 KEY1。

## 内部 Flash

|地址|用途|
|---|---|
|0x08000000–0x08003FFF|Sector 0，中断向量所在区域|
|0x08004000–0x08007FFF|Sector 1，设置日志 A，16 KiB|
|0x08008000–0x0800BFFF|Sector 2，设置日志 B，16 KiB|
|0x0800C000–0x0807FFFF|程序与常量，464 KiB|

向量表仍位于启动地址，复位入口指向代码区，无需额外 bootloader。链接脚本隔离设置扇区，Flash 后端引用链接符号；如果换回未分区的链接脚本，链接会失败。

保存亮度、变暗时间、熄屏时间和抬腕开关。设置静止 1 秒后异步保存，失败间隔 5 秒重试。未修改的默认值不主动写入；相同内容不重复写。不要在每次传感器采样时保存。

每条记录 32 byte，包含魔数、序号、版本和设置、CRC32，以及最后写入的提交标记。单个扇区可容纳 512 条记录；写满后擦除另一个扇区，保留最近已提交的记录所在扇区。启动扫描两区，忽略不完整或校验失败的记录，选择最新有效版本。模拟测试覆盖写入中断和部分擦除；实际低电压条件下的硬件掉电测试仍需上板进行。

STM32F411 从同一 Flash 执行时，擦除/编程可能造成短时 CPU 停顿，异步任务不能消除这种硬件停顿。因此采用低频保存和追加写入，避免频繁擦除。修改后立刻断电可能尚未保存，验证时等待至少 2 秒再复位。

下载建议使用 ELF/HEX 的分段地址。整片擦除会清除设置；连续 BIN 文件会覆盖中间的设置区域，不能用于要求保留设置的更新。

## CubeMX 与构建

`watch.ioc` 同步了 6 个任务的栈和优先级、KEYQueue、两个互斥锁、24 KiB 堆和故障钩子选项。事件组及启动初始化保留在 `freertos.c` 的 USER CODE 块中。当前 CMSIS FreeRTOS 包的普通互斥锁底层使用 FreeRTOS mutex，具有优先级继承。

重新生成后需保留 `STM32F411XX_FLASH.ld` 分区、`lv_conf.h` 和根 CMake 的自定义配置，并重新构建、运行验证脚本。不要用旧 ELF 验证新代码。

正常使用 CMake Debug preset。若 Windows 环境中的 Ninja 启动子进程挂起，可在 CMake 配置后运行 `python scripts/build_firmware.py`，使用同一份 compile_commands 完整编译并通过 response file 链接。

验证命令：

```text
python tests/run_core_logic.py <arm-none-eabi-gcc 的路径>
python scripts/verify_firmware.py
```

模拟测试依赖 `unicorn` 和 `pyelftools`，安装到 `build/test-deps`，不进入固件。81 项检查执行实际 ARM C 代码，覆盖超时边界、计时回绕、显式状态请求、CRC、重复保存、写入中断、擦除失败、部分擦除、扇区轮换和记录序号回绕。

调试器查看 `g_app_diagnostics`：FreeRTOS 当前/历史最少空闲堆，按键、传感器、UI、保存和初始化任务历史最少剩余栈（byte），按键队列丢弃数、保存次数/失败次数、设置加载结果、屏幕状态。`fault=1` 表示分配失败，`fault=2` 表示栈溢出，后者记录任务名。栈预算是初始配置，需通过真实页面和外设运行后的高水位继续确认。

上板验收：连续切换页面与游戏；静置观察变暗/熄屏；分别用 KEY、触摸唤醒并确认首次不误操作；修改四项设置，等待至少 2 秒，复位检查恢复；长期运行检查剩余栈和堆是否稳定。
